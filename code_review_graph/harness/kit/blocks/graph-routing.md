- **Code graph (code-review-graph).** "The code-review-graph tools" means the MCP tools of the `code-review-graph` server, `{{mcp_prefix|mcp__code-review-graph__}}<tool>`; the CLI `code-review-graph` answers the same questions as JSON. Exact symbols, literals and file names go to Grep/Glob. Callers, callees, inheritance, impact radius, dead code, JSP↔Java binding and multi-term structure go to the graph (`query_graph_tool`, `batch_query_tool`, `get_impact_radius_tool`, `semantic_search_nodes_tool`), with an explicit `repo_root`.
- **Entry rule.** No mandatory entry call. Read `_graph.status` in the first graph response. `ok` is ready. `partial_index`, `stale_graph` and `stale_worktree` are degraded with data: the lane is usable, so proceed, say "degraded", cite the `_graph` receipt and its gaps (`missing_indexed_paths`, failed files), and prove gap files by Read. A blocking status (`missing_graph`, `building`, `rebuild_required`, or `error` with an `error_code` such as `schema_too_new`) means heal, then continue: run `crg-heal --repo ROOT --json` once. Exit 0 is ready, 3 usable but degraded, 4 not usable (only then are graph-dependent claims `UNVERIFIED`), 75 busy. Exact-source evidence stays valid throughout.
- **Who heals.** Any agent, once per blocking status, with `crg-heal --repo ROOT --json`; it owns the scope allowlist, the locks and the one-clone-at-a-time cap. Raw `code-review-graph build`, `code-review-graph update`, `code-review-graph clone-graph` and `build_or_update_graph_tool` stay out of agent hands. The PostToolUse hook only refreshes an existing graph and never builds one; `rebuild_required` is re-seeded by `crg-heal` or rebuilt by the nightly postprocess.<!-- if:bug-hunter --> Without an installed `crg-heal`, a blocking status makes graph-dependent claims `UNVERIFIED`; never build by hand.<!-- endif -->
- **Fullstack.** JSP/JSPF/tag, JS, CSS and XML are indexed. RENDERS, REQUESTS (jQuery included), INCLUDES, REFERENCES, FORWARDS_TO, HANDLES (Stripes `@HandlesEvent`/`@DefaultHandler` → `@UrlBinding` Endpoint), BINDS, USES_STYLE and MAPS_TO are all produced since fs.6. `callers_of`/`importers_of` follow only CALLS/IMPORTS_FROM: for page ↔ handler questions use the `query_graph_tool` patterns `pages_for`, `requests_to`, `included_by`, `views_of`, `forwards_to`, `maps_to`, `binds_to`, `styles_of`.
- **Claims.** An impact, callers or completeness claim cites a real graph call; a Grep-only pass supports none. A graph miss is never proof of absence.
