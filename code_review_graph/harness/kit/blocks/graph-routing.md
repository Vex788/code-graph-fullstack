- **Code graph (code-review-graph).** "The code-review-graph tools" means the MCP tools of the `code-review-graph` server, `{{mcp_prefix|mcp__code-review-graph__}}<tool>`; the CLI `code-review-graph` answers the same questions as JSON. Exact symbols, literals and file names go to Grep/Glob. Callers, callees, inheritance, impact radius, dead code, JSP↔Java binding and multi-term structure go to the graph (`query_graph_tool`, `batch_query_tool`, `get_impact_radius_tool`, `semantic_search_nodes_tool`), with an explicit `repo_root`.
- **Entry rule.** No mandatory entry call. The first graph response must carry `_graph.status` of `ok`, or `partial_index` (degraded: say so). Any other status (`missing_graph`, `building`, `rebuild_required`, `stale_graph`, `stale_worktree`, `error`) means `GRAPH_PREP_REQUIRED` for graph-dependent claims; exact-source evidence stays valid.
- **Who builds.** Only the root controller prepares a graph: `build_or_update_graph_tool`, `code-review-graph build`, or `code-review-graph update`. Read-only agents, reviewers and subagents never build or update; they return `GRAPH_PREP_REQUIRED`. The PostToolUse hook only refreshes an existing graph and never builds one; a `rebuild_required` graph needs an explicit build.
- **Fullstack.** JSP/JSPF/tag, JS, CSS and XML are indexed. RENDERS, REQUESTS, INCLUDES and REFERENCES edges exist now; FORWARDS_TO, HANDLES_EVENT (Stripes), BINDS, USES_STYLE, MAPS_TO and jQuery REQUESTS are registered but not produced yet (fs.6+). `callers_of`/`importers_of` follow only CALLS/IMPORTS_FROM: for page ↔ handler questions use the `query_graph_tool` patterns `pages_for`, `requests_to`, `included_by`, `views_of`, `forwards_to`, `maps_to`, `binds_to`, `styles_of`.
- **Claims.** An impact, callers or completeness claim cites a real graph call; a Grep-only pass supports none. A graph miss is never proof of absence.
